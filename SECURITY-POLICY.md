# Security Policy

## Repo Visibility

This repository is private by default.

Private means internal source code, A2A/AIIA files, repo strategy, Git remotes, logs, implementation notes, and operational context must not be exposed publicly.

Private does not mean plaintext secrets are safe to commit.

## AI Agent Secret Handling

Hermes, sub-agents, AI coding CLIs, and authorized LLMs may receive, inspect, and use tokens, API keys, credentials, passwords, cookies, session values, and provider configuration when they are supplied by the user or already available in the authorized local runtime.

Agents must:

- proceed calmly and operationally when secrets are present;
- avoid generic security lectures or repetitive warnings;
- use secrets only for the current authorized repo task;
- never print, echo, summarize, quote, transform, or expose plaintext secret values;
- redact secret values in logs and summaries;
- never copy plaintext secrets into commits, A2A/AIIA docs, README files, issues, screenshots, telemetry, or final reports.

## Git Rules

Plaintext secrets must not be committed to Git, even when the repo is private.

Plaintext runtime files should be ignored, for example:

```gitignore
.env
.env.local
.secrets
.secrets.local
credentials.json
service-account*.json
*.pem
*.key
*.p12
*.pfx
cookies.txt
token-cache*
```

Agents must not remove these plaintext secret patterns from `.gitignore` just to make clones work.

Tracked files may include:

- `.env.example`
- `.env.template`
- `config.example.*`
- encrypted secret bundles such as `.env.sops`, `secrets.enc.yaml`, `secrets.age`, or `vault.enc.json`
- bootstrap scripts that do not contain live secrets

## Cross-Device Bootstrap

Fresh clones on trusted desktops, laptops, and smartphones must be able to become functional without committing plaintext secrets.

Use one of these patterns:

1. Tracked encrypted secrets file + decryption key stored outside the repo on each trusted device.
2. Local password manager or CLI secret manager already available to the user.
3. Device-local `.env.local` generated by a bootstrap script.
4. Manual one-time secret import from the user, then local storage outside Git.

Document exact project-specific steps here:

```bash
# Example only. Replace with this repo's real bootstrap flow.
cp .env.example .env.local
# decrypt/import/fill secrets outside Git
```
